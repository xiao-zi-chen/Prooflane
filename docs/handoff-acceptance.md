# 执行与证据验收

**简体中文** · [English](handoff-acceptance.en.md)

由执行者填写环境和观察，复核者确认结论。这个表是交付约定，不表示下面的检查已经通过。

## 执行前

- [ ] 应用方、协调者、执行者、复核者及回传渠道明确。
- [ ] 平台、版本、架构、物理机 / 虚拟机 / WSL2、X11 / Xvfb 等环境信息已登记。
- [ ] 文件 SHA-256 与 scenario.json 一致；相同版本号但不同哈希视为不同构建。
- [ ] 步骤、窗口标题、控件定位、安装参数、预期文本完整；每个平台用本平台构建。
- [ ] 执行者确认测试环境可用、桌面空闲，已处理必要权限。

## 执行后

- [ ] 返回完整 evidence.zip 和 receipt.json；预检失败时提供原始错误文本和环境信息。
- [ ] receipt 的 source_run_id 与分派任务一致；execution_run_id 与包内 report.json 对应。
- [ ] 根据 evidence.zip 的实际内容重新计算 SHA-256，与回执一致；哈希只说明文件一致，不证明报告可信。
- [ ] 报告中的构建 SHA-256、平台、架构、步骤数量及定位配置与原始任务一致。
- [ ] 每个已执行步骤的截图确实是目标应用；截图和录像能够打开，并对应实际操作。
- [ ] report.json、feedback.md、执行 / 应用日志、controls.json 以及可用的崩溃信息齐全；缺项写明原因。
- [ ] 截图验收、黑屏、录像缺失或权限错误没有被当成自动检查通过。
- [ ] 所有失败与中断记录保留；同一构建建议复跑 3 次，分别交付证据。
- [ ] 涉及修复时以新构建哈希重新执行，保留旧结果作为对照。

## 结论规则

| 状态 | 判定与下一步 |
| --- | --- |
| 未执行 | 仅交付了策略或尚无运行证据；继续安排执行者 |
| 环境阻塞 | 当前环境无法执行；记录原因后由执行者修复环境 |
| 执行失败 | 自动执行出现失败；结合原始证据区分应用、输入和适配问题 |
| 待复核 | 自动步骤或部分证据已完成，但人工布局检查、证据完整性或可信度尚待确认 |
| 已验证 | 复核者确认本构建、场景和指定环境满足验收要求；只覆盖本次明确的范围 |

独立执行器的 execution_status 与复核结论分开。receipt.json 的 review_status 默认 pending，即使自动检查 passed 也需要复核者核验。人工操作的证据应单独标记，不能计为自动化适配成功。

当前控制台不提供独立结果 ZIP 的自动导入与可信认证；不要手动修改服务端数据库来把等待任务改成通过。复核者使用 STRATEGY.md 的登记表追踪独立结果，或另行安排在线节点运行同一场景。
