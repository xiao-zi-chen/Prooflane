# 问题排查

**简体中文** · [English](troubleshooting.en.md)

先查看失败步骤的原始错误、运行日志和控件清单。把问题记在[问题模板](issue-template.md)中，保留首次失败的证据；不要用修改预期值来掩盖失败。

## 控制台无法启动

| 现象 | 检查与处理 |
| --- | --- |
| 提示缺少模块 | 确认使用项目虚拟环境的 Python，并重新安装对应 requirements 文件 |
| 端口 8765 已占用 | 确认是否已有服务；需要第二个控制台时使用其他端口和独立数据目录 |
| 数据目录已有执行器 | 停止重复进程；不要启用多个 Uvicorn workers，也不要让两个节点操作同一桌面 |
| Windows 示例编译失败 | 检查 .NET Framework C# 编译器；示例编译与上传自己的应用是独立功能 |
| `Invalid host header` | 使用 localhost 或明确配置的 Host，参见[配置说明](configuration.md) |

## 任务一直等待节点

在“执行节点”中核对目标平台、架构和就绪状态。

1. 没有该平台节点：导出执行包交给测试者，或由测试者接入节点。
2. 节点在线但未就绪：查看节点给出的桌面、依赖或权限错误。
3. 架构不同：`arm64` 任务不会交给 `x86_64` 节点；不要为了排队通过而随意改成 `any`。
4. 已有任务占用该节点：等待当前任务结束，确认桌面未被其他进程使用。

更改配置后，重新查看就绪状态。仅“在线”不代表任务已执行。

## macOS 权限或启动失败

给实际运行节点的终端 / Python 授予辅助功能和屏幕录制权限，然后重启该进程。必须从已登录的图形桌面启动；SSH 终端不能替代桌面授权。

APP 的 ZIP 包中含符号链接时，解包检查会拒绝。带 Framework 链接的应用可提供 DMG。PKG 的安装路径、权限、签名或 Gatekeeper 问题应保留原始提示，执行器不会自动提权或关闭系统保护。

当前 macOS 适配器尚未完成实机验证；请记录 Mac 架构、系统版本、应用框架和权限状态。

## Linux 环境未就绪

需要 X11、AT-SPI / PyGObject、D-Bus 和 XComposite。Wayland 暂不支持。系统依赖安装命令和 Xvfb 启动方式见[节点接入](multiplatform.md)。

- 导入 `gi` 失败：核对发行版依赖和 `--system-site-packages` 虚拟环境。
- 无法找到应用控件：核对 AT-SPI、D-Bus 会话及应用的可访问性支持。
- AppImage 启动失败：保留 FUSE 或运行库错误，先归类为环境问题。
- 使用 WSL2 / Xvfb：在回执中明确标记，不能当作 Wayland 或物理 GPU 覆盖。

## 找不到窗口或控件

核对窗口标题、`target`、`automation_id`、控件类型和步骤顺序。查看 `controls.json`，确认记录来自这次运行的应用。不同系统的控件 ID 和类型可能不同，需要按平台配置。

若人工操作可以完成而自动化失败，先记录为“自动化问题待确认”。自绘界面或不暴露可访问性信息的控件，可能需要人工补充验证。

## 截图黑屏、录像缺失或无法播放

查看采集错误和文件是否完整，核对桌面权限、窗口状态以及运行是否中断。Windows 采集按目标窗口执行；Linux 依赖 XComposite；macOS 需要屏幕录制权限。

不能把空白截图或缺失录像当作通过证据。保留日志和现有产物，按[验收要求](handoff-acceptance.md)登记证据缺口。

## 独立执行包不能运行

| 现象 | 处理 |
| --- | --- |
| 提示通用策略或缺少运行模块 | 回到“执行策略”选择具体任务，再下载执行包 |
| SHA-256 不一致 | 取得任务对应的原文件，或创建新任务后重新导出；不要直接改清单哈希 |
| 系统或架构不匹配 | 使用对应系统和架构的测试环境 |
| 预检失败，没有结果目录 | 回传终端错误与环境信息；预检不会安装或启动应用 |
| 执行结束但控制台仍等待 | 这是独立结果，需人工复核；当前没有自动导入接口 |

## 节点连接和回传失败

`401` 通常需要检查注册凭据或节点专属凭据；`403` 还可能表示任务归属不符。确认转发地址、端口和凭据来自同一控制台。

断连超过租约后任务会中断，旧结果不会覆盖新状态。节点本地可能保留证据，应先检查再决定复测。重复安装前确认应用当前状态。
