# 测试环境安排

这份说明用于联系有 macOS / Linux 设备的测试者。设备采购和日常维护由执行者安排，项目负责提供任务、工具和验收方式。当前没有可公开的 Mac 或 Linux GUI 通过记录。

## 候选来源

| 来源 | 先确认什么 |
| --- | --- |
| 同事或内部 QA | 系统、架构、可用时段，是否能运行测试构建 |
| 客户 QA 或合作伙伴 | 可交付的包、采集范围、结果返回方式 |
| 社区测试者 | 先用公开样本检查流程，再约定业务包和资料范围 |
| 测试服务商或云桌面 | 图形桌面、依赖安装、权限设置、总费用和最短计费周期 |

供应商价格和库存会变化，请由安排设备的人在下单时确认。这里不维护未经持续核实的报价或推荐名单。

## macOS

需要符合 Apple 授权条件的 Mac 环境、Python 3.11+ 和实际用户桌面。测试者应能给运行程序的终端 / Python 授予辅助功能与屏幕录制权限。

Apple Silicon 与 Intel 分别登记。只有 SSH 或只能执行编译任务的环境，不应直接作为可用 GUI 节点。先取得一个完整样本的截图、录像和日志，再确认该环境的覆盖范围。

## Linux

当前适配器需要 X11、AT-SPI / PyGObject、D-Bus 和 XComposite，Wayland 暂不支持。首轮可以选择 Ubuntu 24.04；其他发行版需另行确认包名与运行库。

| 环境 | 记录方式与限制 |
| --- | --- |
| 物理机 / 虚拟机的 X11 桌面 | 记录发行版、版本、架构和桌面会话 |
| 无桌面服务器上的 Xvfb | 标记为虚拟显示；不能推断物理 GPU 或 Wayland 的表现 |
| WSL2 加 Xvfb | 同时记录 WSL2 与 Xvfb；不代表物理 Linux 桌面兼容性 |

系统依赖与项目辅助脚本见[节点接入](multiplatform.md)。辅助脚本的存在不代表该环境已经实测通过。

## 发任务前的确认消息

```text
想请你协助测试一个桌面应用。
目标系统和架构：
应用版本及构建获取方式：
验收步骤：
预计可执行时间和费用：
结果返回方式与保留期限：

我们提供执行包和说明。请先确认能安装依赖、运行应用并采集窗口。
运行后返回回执、证据 ZIP；如果受阻，返回原始错误和环境信息即可。
```

首轮优先[独立执行](execution-strategy.md)，不需要测试者开放机器密码或连接控制台。双方需要持续自动测试时，再约定[在线节点](multiplatform.md)。

## 如何确认可用

“找到设备”“连接成功”“节点就绪”和“完成验收”是不同阶段。收到构建标识、环境信息、实际步骤和可打开的证据后，按[证据验收](handoff-acceptance.md)登记结论。
